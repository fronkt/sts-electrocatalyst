# S1 — the CI harness, handed off. 2026-08-27

**What this is.** The registered A9.2 controls and the A9.1 disjointness assertion now
exist as runnable CI, together with a test suite and a fixture manifest. What does *not*
exist, and is not created by anything in this commit, is `silentgate/` itself. The core is
"written and committed only by the entrant" (docs/43:1840). This document is the hand-off:
what was built, what was deliberately not built, what CI says today, and the seven decisions
that stand between here and a green face.

Everything here was produced under the permission A9.1 :1840 grants — *"AI may write tests
and fixtures, the CI workflow, and review comments"* plus the adopted narrow packaging
clause — and under A9.6 :1964, which says in terms that *"CI may be built against `runs/`."*

## 2. What was deliberately not built

Three refusals, each of which cost something and each of which is the point.

**No shadow reader in the harness — and therefore no numeric expectations.** The obvious
way to write these tests is to compute the expected census independently and assert the
core reproduces it. That would mean a per-atom / per-axis / per-step force-block parser,
which is `silentgate/readers/*`, which is core. Worse, it would put a second unreviewed
detector in the repo and leave a genuine question — *whose census is right?* — with no
registered answer. So the fixture manifest records only **structural** facts, and numeric
expectations become **golden files** generated by your core and reviewed by you (§6). No
file in `.github/ci/` or `tests/silentgate/` parses a pw.x output.

**But one was written earlier the same day, and §4(c) discloses it.** Choosing the thirteen
fixtures needed to know which files carry which trap, and an AI survey script did that by
parsing every force block under `runs/`. It is preserved at
`docs/research/ai-survey-2026-08-27/`. Producing it was permitted and anticipated — :1445
lists "sweeps" among what the provenance record covers — but it measured two quantities the
registered text calls not-yet-measured, and that needs your ruling. See §4(c). The
`pins`/`decides` prose in the fixture manifest is downstream of that survey; the manifest
header now says so, because an earlier draft of it claimed the file contained no verdicts
while its own prose stated several.

**No file under `silentgate/`, not even `__init__.py`.** `__init__.py` is not one of the
five named core paths, so an assistant could have written it inside the letter of the rule.
The rule's sentence is *"AI may not author the object the project is named after"*, and a
package initialiser for that object is part of it. Nothing under `silentgate/` was written.

**No election of an open registered parameter, anywhere.** Seven decisions are open (§5).
Every place where CI would otherwise have to assume one, it fails closed and names the
decision instead. In particular `.github/ci/silentgate-invocation.toml` is entirely blank:
hard-coding a command line and a JSON shape would have designed your CLI's interface by the
back door, and `cli.py` is core. You declare the interface there; CI supplies the mechanism.

## 3. What CI says today, and what red means

`.github/workflows/s1-controls.yml` runs three jobs on every commit: `oc20`, `face`, and
`tests`. **Expect `face` to be red until you commit the core.** That is not a defect; A9.2
is registered as a gate — *"P-CTRL therefore voids rather than caveats"* (:1848) — and a
gate whose instrument does not exist is not green.

The face is designed so a red run is never ambiguous. Today:

```
silentgate S1 control face
  commit: f0b72e2...

  silentgate core present                              ABSENT       FAIL  docs/43:1840
  provenance record INTERSECT core paths = {}                 MEASURED     FAIL  docs/43:1840
  positive control: 9/9 LOCKED, nosym-absent           NOT MEASURED ----  docs/43:1864
  QE negative control: 0/11 LOCKED, force-only         NOT MEASURED ----  docs/43:1858
  20-for-20 partition by the deck's nosym line         NOT MEASURED ----  docs/43:1864
  header-vs-force agreement, n/n classifiable rows     NOT MEASURED ----  docs/43:1864
  tag-free adsorbate rule reproduces tag counts 20/20  NOT MEASURED ----  docs/43:1834
  OC20 negative control: exactly 0.00 % of 500         NOT MEASURED ----  docs/43:1856

RESULT: NOT GREEN
```

Two rows read `FAIL` (something is missing that you control); six read `NOT MEASURED`
(the registered vocabulary of :1868, and honest — nothing has been measured). Every row
carries the line of docs/43 it comes from. The `tests` job, by contrast, is **green today**
(46 passed, 7 skipped) and stays green: it checks that the harness itself is sound, so if
it ever goes red that is a real regression, not the absence of the core.

`tests/silentgate/test_gate_fails_closed.py` is the tripwire on the tripwire — seventeen tests
proving the gate *cannot* go green while the core is missing, while the provenance record is
missing, while the OC20 job has not run, or if the core path list is ever widened to
`silentgate/**`. Those must keep passing after the core lands.

**The face is also proved *passable*.** A gate that can never go green is as broken as one
that always does, and "it is red because the core is missing" would happily hide a bug that
kept it red forever. `test_face_end_to_end.py` drives the whole face through a test double
(`fixtures/fake_census.py`, which parses nothing — it looks paths up in `populations.txt`
and emits the scenario's answer) and checks that with every control at its registered
passing value the **only** red row left is `core_present`. Nine further scenarios each break
one registered threshold and check that exactly the right gate goes red: a null verdict, one
LOCKED run in the eleven, a misplaced deck, a tag-count disagreement, a two-witness
disagreement, an empty census, a missing log, a missing OC20 verdict, a nonzero OC20 rate.

Two real bugs surfaced from writing those. `run_controls.py` substituted paths into the
command string *before* `shlex.split`, so a Windows path arrived at the tool with its
backslashes eaten — the template is now split first and the values substituted into the
argv. And `core_present` tested only that `silentgate/` was a directory; an empty directory
would have read PRESENT and let the face claim an instrument that does not exist. It now
names the five module paths.

The corpus tripwires are deliberately **one-sided**. S3 is live and adding outputs, and a
check that fired on every legitimate new run would train you to ignore CI — which is the
only way a gate actually fails. So the suite fails when a tracked output *disappears*, when
a fixture's content changes, or when an **unrecognised symmetry-header form appears** (a
real risk to the reader); ordinary growth is reported and allowed.

The repo's fourteen pre-existing test modules are untouched: 100 passed, unchanged.

## 4. Three corrections of record found while building this

**(a) A9.1 :1834's `if_pos` rationale is false for QE 7.5.** The registered sentence reads:
*"atoms with any `if_pos = 0` are excluded from every exact-zero count and their number
reported (pw.x prints the if_pos-masked force, so a fixed coordinate reads exactly zero for
a reason that is not symmetry)."* Re-measured from scratch on 2026-08-27 over five
deck/output pairs in five metals — 49 frozen atoms, every ionic step of each run,
**704 frozen-atom force observations: not one prints all three components exactly zero.**
`runs/s3/Mn/ref__2x1v.in` atom 12, flagged `0 0 0`, prints z = 0.04355221 Ry/bohr; the
largest frozen-atom component seen is 0.08723744 in `runs/Cr_slab/s0_O.out`. If the mask
were applied a `0 0 0` atom would print `0.00000000` on all three axes, and none does.
(A frozen atom *can* print an exact zero on one axis — `runs/Cr_slab/s0_O.out` atom 1 reads
`0.00000000 0.00000000 0.08723744` — but that is the symmetry witness doing its job, which
is the opposite of the registered claim.) The **action** stays right — excluding them is
cheap, correct for other codes, and
adsorbate atoms are always `1 1 1`, so no production verdict moves. What changes is a risk
assessment: frozen atoms were named as a false-LOCKED source and in this code they cannot
be one. Registered as open question `if_pos_parenthetical`.

**(b) The pw.x symmetry header has four textual forms in this repo, not one.** A9.1 :1836
registers that the reader *"accepts both forms by regex and logs the form encountered per
file"*, where "both" means pw.x 7.5's count-first form and the count-**last** form shown in
`symops_audit.py`'s own docstring. Censused over all 515 tracked outputs on 2026-08-27:

| form | files |
|---|---|
| `N Sym. Ops. (no inversion) found ( N have fractional translation)` | 128 |
| `N Sym. Ops., with inversion, found` | 21 |
| `N Sym. Ops. (no inversion) found` | 13 |
| `N Sym. Ops., with inversion, found ( N have fractional translation)` | 11 |
| `No symmetry found` (no header line) | 312 |
| neither marker | 30 |

**Zero** files use the count-last form. A regex anchored on `(no inversion)` misses 32 of
the 173 files that carry a header — the legacy `SYMOPS` regex is anchored on `(\d+)\s+Sym\.
Ops\.` and survives all four, which is worth knowing before v0.1 rewrites it. And A9.7's
act-2 dated line (2026-08-23) already looked for the count-last form in the Xu deposit and
recorded that all four validated RuO₂ files are count-first. So the both-forms rule stands
but has been exercised against **no real count-last data anywhere**; P-XU's six blind
metals are still unread and cannot rule it out. Pinned in the fixture manifest so
"accepts both forms" is never mistaken for "tested on both forms".

**(c) An AI script measured two quantities the registered text calls not-yet-measured.**
Choosing the thirteen fixtures required knowing which files carry which trap, and an AI
survey (`docs/research/ai-survey-2026-08-27/sweep.py`, written 16:51 on 2026-08-27, ~40
minutes before the first CI file) got that by parsing every pw.x force block under `runs/`
per atom, per axis, over every ionic step. Writing it was permitted and anticipated: :1445
lists *"sweeps"* among what the provenance record covers, and nothing under `silentgate/` was
written.

What it also did was census **F_x** on the registered P-CTRL populations:

> :1858 — *"it passes today on y ... and is **unmeasured on x** until v0.1 reports it."*
> :1864 — *"**F_x was never censused by the current code and is reported by v0.1**."*

| population | n | F_x zero every step | F_y zero every step |
|---|---|---|---|
| `nosym_absent` | 9 | **3** | 9 |
| `nosym_present` | 11 | **0** | 0 |

The three are `Cr_slab/s0_O.out`, `Ir_anchor/s0_O.out`, `Ru_anchor/s0_O.out` — the
`n_symops = 4` 1x1 *O runs, exactly the class :1864 predicts locks x by inference. **The
registered prediction is confirmed.** The y figures are not new: :1858, :1864 and :1964
already register 9/9 and 0/11 as the published record. The x half is what changed status.

Why it matters: F4 (:1848) makes P-CTRL a gate *because* "every number flows through code
written by the person who believes the trap is real." A control whose expected answer is
published before the detector is written is weaker than one whose answer is not. That is a
reason to disclose, not a reason the numbers are wrong. Nothing in CI is scored against
these numbers, no test asserts them, and a test forbids the harness from referencing them.
Registered as open question `ai_x_census_disclosure`.

None of the three corrections changes a threshold. All three are yours to file.

## 5. The seven open decisions

Registered in `tests/silentgate/spec_rulings.toml`. Each is elected by **a dated line in
docs/43**; the TOML only records that the line exists, so CI can see it. While
`silentgate/` is absent these tests skip; the moment the core lands they fail until each is
recorded. Two of them block CI *today*.

| # | id | the question | blocks today? |
|---|---|---|---|
| 1 | `adsorbate_quantifier` | ANY adsorbate atom, or ALL, for the run-level LOCKED verdict? | no |
| 2 | `truncated_force_block` | Is a force block missing its leading atoms scorable? | no |
| 3 | `oc20_ci_mechanism` | Release asset, or self-hosted runner? | **yes** |
| 4 | `ai_use_log_path` | Where does the provenance record live? | **yes** |
| 5 | `if_pos_parenthetical` | File the correction of record above? | no |
| 6 | `pyproject_build_system` | Is `[build-system]` inside "packaging"? | no |
| 7 | `ai_x_census_disclosure` | How is the AI's force-only **x** census disposed of? (§4c) | no |

**5.1 The quantifier decides the registered `n/n` by exactly one row.** :1858 words the
negative control as *"any adsorbate atom"*; :1830's run-level rule words the positive side
as *"every adsorbate atom"*. Over the 96 classifiable rows the agreement is 96/96 under
ALL and 95/96 under ANY. The single flip is `runs/probe/Ru/s0_OH__dipole.out`, where atom
19 prints `-0.00000000` on y and atom 20 does not. Note the deciding token is a **negative
zero**: a string comparison against `"0.00000000"` misses it, and 117 of 480 outputs carry
it.

**5.2 Truncated blocks.** Eighteen outputs have MPI abort text spliced in, leaving a NUL
byte; in nine the force-block header is destroyed and the block starts partway through the
atom list — `runs/probe/Cr/s0_OOH__base.out` runs atoms 12–21 of 21. Three archived LOCKED
rows rest on such blocks. The adsorbate atoms are present and exactly zero on y in all
three, so the verdicts are defensible, but a detector requiring a complete `1..nat` block
drops them and changes the LOCKED count. Either answer works; leaving it implicit means the
answer is whatever the parser happens to do. (Related: a NUL byte makes `grep` treat the
file as binary and skip it silently — that is how this family stayed invisible.)

**5.3 The OC20 transport.** :1868 leaves it open in terms and adds: *"Under either, a
commit on which the OC20 job did not execute is not green."* Both mechanisms are
implemented in `run_oc20.py`; neither is defaulted. To elect (a): publish the 500-file
sample as a release asset and set repo variables `S1_OC20_MECHANISM=release-asset` and
`S1_OC20_ASSET_URL`. To elect (b): register the STS machine as a self-hosted runner and set
`S1_OC20_MECHANISM=self-hosted`, `S1_OC20_SAMPLE_DIR`, and `S1_OC20_RUNNER` to its label.
Either way the sample is verified file-by-file against the already-committed
`docs/research/oc20-val_id/first500.SHA256SUMS` before anything is scored; a mismatch is a
transport failure to fix, never a reason to re-draw (:1854).

**5.4 The provenance record's path.** Named as an obligation five times in docs/43 and never given
a path. `check_disjoint.py` fails closed on a missing log — an absent log leaves the file
list *undefined*, not empty, and a vacuous pass would make the check strongest exactly when
nobody is logging. Set `S1_AI_USE_LOG`, or give the log a filename matching
`/ai[-_]?use|ai[-_]?log|use[-_]?log/`. The extractor is format-agnostic: it pulls every
path-like token out of whatever you write and tests each against the five core patterns, so
no schema needs registering, and over-extraction can only ever make the assertion fail
loudly, never pass.

**5.5 and 5.6** are §4(a) and the `pyproject` stretch flagged inline in that file.

## 6. When the core lands

1. Fill `.github/ci/silentgate-invocation.toml` — the two commands and the JSON pointers.
   Field names on the left of `[schema]` are registered quantities with their citations;
   the pointers on the right are yours, so your field names stay yours.
2. Record the six rulings in `tests/silentgate/spec_rulings.toml`, each with its dated line.
3. Run `python .github/ci/run_controls.py` locally. It will print the face with the
   controls MEASURED.
4. **Golden files.** Once the face is green, freeze the census output for the thirteen
   manifest fixtures as golden files and commit them. From then on the suite catches a
   changed verdict, and the numbers in it are yours, reviewed by you — which is the only
   way a numeric expectation can enter this repo without an assistant having authored a
   second detector.

The controls run in seconds against `runs/`; only OC20 needs transport. A9.6 :1964 confirms
all of this was already permitted before the DOI line, and the DOI line has existed since
2026-08-23, so nothing here is gated on anything but the core.

## 7. Running it locally

```
python .github/ci/check_disjoint.py --json disjoint.json
python .github/ci/run_oc20.py       --out-json oc20.json
python .github/ci/run_controls.py --disjoint-json disjoint.json --oc20-json oc20.json
python -m pytest tests/silentgate -q
```

The first three exit nonzero while their gate is unmet. The last should print
`46 passed, 7 skipped`. Running the repo's whole suite together — `python -m pytest tests -q`
— gives `146 passed, 7 skipped`, the pre-existing 100 unchanged.

To refresh the fixture manifest after a legitimate corpus change:
`python tests/silentgate/fixtures/regenerate_manifest.py`, then commit the diff.
